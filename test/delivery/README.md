Run the local delivery contracts with `mise exec -- python3 -B -m unittest discover -s test/delivery -p '*_test.py'`.

The suite uses temporary repository copies, real Kustomize/Helm rendering and local CLI fakes. It never connects to a Kubernetes API or registry. Removal inventory and image build records prove command orchestration only. Real PostgreSQL retention, Helm ownership rejection, runtime image identity and CRD lifecycle require the separate disposable Kind gate.

The accepted interfaces are `tools/deploy.sh build-installer` (both `dist/install.yaml` and controller-only `dist/uninstall.yaml`), controller-only `undeploy`, and CRD retirement through `uninstall` with explicit `KUBE_CONTEXT` and `ACK_CRD_RETIREMENT=delete-all-epco-crds`. Chart generation uses `python3 tools/chart.py sync|check --chart-dir PATH --inputs-dir PATH`; inputs directly contain `crd/bases/` and `rbac/role.yaml`. `check` detects drift without writing.

The real `lifecycle.py` helper is dispatched through `test/e2e/run.sh` with `EPCO_E2E_SUITE=delivery`. It inherits the runner's private kubeconfig, owned `kind-epco-e2e-*` context and PostgreSQL fixture. Supply `EPCO_DELIVERY_CHART_PACKAGE` as an exact local `.tgz`, `EPCO_DELIVERY_IMAGE_REFERENCE`, and separate `EPCO_DELIVERY_IMAGE_SOURCE_SHA` / `EPCO_DELIVERY_CHART_SOURCE_SHA`. `EPCO_DELIVERY_LOCAL_IMAGE=true` explicitly limits evidence to local mechanics; release-artifact mode requires tag plus digest. The helper writes sanitized pass/fail evidence to `delivery-lifecycle.json`; private Secret/SQL snapshots remain only in memory. Runner diagnostics and owned-cluster cleanup are reused.
